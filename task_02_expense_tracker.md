  # Задача 2. Трекер личных расходов

**Уровень:** средняя

## Описание

Веб-приложение для учёта личных расходов. Пользователь добавляет траты с категорией, суммой и датой, приложение показывает список всех трат, общую сумму и разбивку по категориям. Все данные сохраняются в браузере — после перезагрузки страницы ничего не теряется.

Реальная польза: ты сам потом сможешь понять, сколько денег уходит на доставку еды, такси и подписки.

## Требования

1. Форма добавления траты: категория (выбор из списка, например: еда, транспорт, развлечения, подписки, прочее), сумма в тенге, дата (по умолчанию сегодня), необязательное описание.
2. Список всех добавленных трат — каждая с категорией, суммой, датой, описанием и кнопкой «Удалить».
3. Общая сумма всех расходов отображается крупно.
4. Сумма по каждой категории — отдельным блоком или таблицей.
5. Все данные сохраняются в `localStorage`. При перезагрузке страницы или закрытии браузера траты остаются на месте.
6. Когда трат ещё нет — на странице понятная подсказка «Добавьте первую трату», а не пустая дыра.
7. При удалении траты — общая сумма и сумма по категории пересчитываются мгновенно.

## Технические ограничения

- Стек: чистый HTML, CSS, JavaScript.
- Запрет: React, Vue, jQuery, CDN-библиотеки для основной логики. Стилизация — свой CSS или любая чистая CSS-библиотека (например, Pico.css) допустима.
- Хранилище: только `localStorage`. Никаких серверов и баз данных.
- Сервисы: GitHub Pages для деплоя.

## Критерии готовности

- Деплой работает по ссылке.
- Добавление траты через форму → она мгновенно появляется в списке.
- Удаление траты → она исчезает из списка, общая сумма и сумма по категории пересчитываются.
- Перезагрузил страницу (F5) → все траты на месте.
- Удалил все траты → страница показывает пустое состояние с подсказкой, не падает с ошибкой.
- Открыл DevTools → Application → Local Storage → видно сохранённые данные в формате JSON.
- README оформлен по шаблону, со скриншотом или гифкой.

## Защита проекта

Студент должен уметь объяснить:

- Что такое `localStorage` и в чём принципиальное отличие от обычной переменной JavaScript. Что произойдёт с данными, если открыть приложение в режиме инкогнито или в другом браузере.
- Где в коде сохранение в `localStorage` и где загрузка из него. Почему данные сериализуются через `JSON.stringify` и парсятся через `JSON.parse`.
- Что произойдёт, если в `localStorage` вручную положить невалидный JSON (через DevTools), и как код это обрабатывает. Можно проверить прямо в браузере.
- Где в коде происходит подсчёт общей суммы и по категориям. Это пересчитывается каждый раз заново или хранится отдельно?

## Подсказка для работы с ИИ

Если застрял на `localStorage` — попроси Cline объяснить разницу между `localStorage` и `sessionStorage`, и почему массив объектов нельзя сохранить напрямую без `JSON.stringify`. Хороший приём: открой DevTools → Application → Local Storage и попроси Cline добавить `console.log` после каждого сохранения. Так ты будешь в реальном времени видеть, как меняются данные в хранилище.

## Заметка про конфиденциальность

Все данные хранятся локально в браузере и никуда не отправляются. Это правильный подход для финансовых приложений — никто не хочет, чтобы его личные траты лежали на чужом сервере. На второй неделе мы будем работать с реальными базами данных, и тогда обсудим, какие данные можно класть на сервер, а какие — нет.
